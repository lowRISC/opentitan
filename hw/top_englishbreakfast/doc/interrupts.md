# Englishbreakfast Interrupts

## Vector Table

Software writes `mtvec` with the vectored mode bit set.
Ibex then jumps to the `mtvec` base address for every synchronous exception, and to the base address plus `4 * N` for interrupt cause `N`.
The Ibex input an interrupt arrives on fixes its slot.
The [Ibex documentation](https://ibex-core.readthedocs.io/en/latest/03_reference/exception_interrupts.html) describes the mechanism.

| Slot   | Offset        | `mcause`                  | Ibex input       | Source                                                       |
|--------|---------------|---------------------------|------------------|--------------------------------------------------------------|
| 0      | `0x00`        | Exception code            |                  | Synchronous exceptions                                       |
| 3      | `0x0C`        | `0x80000003`              | `irq_software_i` | `rv_plic.msip`                                               |
| 7      | `0x1C`        | `0x80000007`              | `irq_timer_i`    | `rv_core_ibex_irq_timer`, assigned in the top-level template |
| 11     | `0x2C`        | `0x8000000B`              | `irq_external_i` | `rv_plic.irq`                                                |
| 16-30  | `0x40`-`0x78` | `0x80000010`-`0x8000001E` | `irq_fast_i`     | Tied to 0 in `rv_core_ibex`                                  |
| 31     | `0x7C`        | `0x8000001F`              | `irq_nm_i`       | `NMI_STATE` of `rv_core_ibex`                                |

The other slots have no source.

## Non-Maskable Interrupt

`rv_core_ibex` drives `irq_nm_i` when a bit is set in both `NMI_STATE` and `NMI_ENABLE` (see its [registers](../ip_autogen/rv_core_ibex/doc/registers.md)).
`NMI_ENABLE` is write-1-to-set and `NMI_STATE` is write-1-to-clear.

| Field             | Source                                                |
|-------------------|-------------------------------------------------------|
| `NMI_STATE.ALERT` | Not connected, tied to `prim_esc_pkg::ESC_TX_DEFAULT` |
| `NMI_STATE.WDOG`  | Not connected, tied to `'0`                           |

## PLIC Interrupt IDs

The PLIC drives `irq_external_i` while an enabled interrupt is pending above the priority threshold.
Software reads the claim register of its target to get the ID of the highest-priority pending interrupt, and writes the ID back to complete it.
ID 0 means no interrupt is pending.
