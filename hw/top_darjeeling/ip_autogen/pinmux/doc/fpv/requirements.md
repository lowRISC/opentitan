# Pinmux FPV requirements

This page lists what the Darjeeling pinmux must do, one testable requirement per row, grouped by feature.

* Each row gives the requirement, its sources, and the checks that decide it with the reason.
* A row of kind `spec` holds a rule that a specification states. A row of kind *RTL* holds a rule that no specification states, so it follows the design's present behaviour. A mark such as (*RTL*: the length of the bound) flags one such part in a `spec` row.
* A group's Conditions say when its rows hold. A number of cycles that only a check gives is the window that the plan sets for that check.
* A value that the top sets is written as a [parameter](#parameters).
* The [Pinmux FPV testplan](README.md#how-the-plan-fits-together) shows how the requirements, the testpoints and the checks fit together. [`pinmux_fpv_requirements.hjson`](../../data/pinmux_fpv_requirements.hjson) holds the same rows as data.

## Terms

| Term | Meaning |
|---|---|
| `n` | MIO peripheral input, from 0 to `NMioPeriphIn` - 1 |
| `k` | MIO peripheral output, from 0 to `NMioPeriphOut` - 1 |
| `p` | MIO pad, from 0 to `NMioPads` - 1 |
| `d` | DIO pad, from 0 to `NDioPads` - 1 |
| Watched signal | The pad input that `MIODIO` and `PADSEL` pick |
| Forwarded value | The watched signal sampled each `clk_aon_i` cycle, through the filter when `FILTER` is 1 |
| Asleep, awake | A pad is asleep while its sleep status bit is 1, awake while it is 0 |
| AON | The always-on domain: the logic on `clk_aon_i` and `rst_aon_ni` |
| Lands | A written or sampled value lands in the cycle the register or flop it is meant for takes it |
| Hardware write | A write to a register field made by the pinmux logic, not by software over the bus |
| Allowed pad | A pad is allowed for a signal when the signal's pad list names the pad, or when the list is empty. The pad list is the signal's `pads` entry in the top's configuration ([top_darjeeling.hjson](../../../../data/top_darjeeling.hjson); [top_darjeeling_pinmux.ipconfig.hjson](../../data/top_darjeeling_pinmux.ipconfig.hjson) `mio_periph_ins`; [top_darjeeling_pinmux.ipconfig.hjson](../../data/top_darjeeling_pinmux.ipconfig.hjson) `mio_periph_outs`). |

## Parameters

The requirements name each value by its parameter, so the same rows hold for every top.

| Parameter | Meaning | Value on Darjeeling |
|---|---|---|
| `NMioPeriphIn` | Number of muxed peripheral inputs | 4 |
| `NMioPeriphOut` | Number of muxed peripheral outputs | 5 |
| `NMioPads` | Number of muxed pads | 12 |
| `NDioPads` | Number of dedicated pads | 73 |
| `NWkupDetect` | Number of wakeup detectors | 8 |
| `WkupCntWidth` | Width of a wakeup detector's counter, in bits | 8 |

## Pad attributes

Conditions:

* Every row holds in every cycle, whether the pad is asleep or awake.
* "Written" means a write that the register block accepts while the register's lock is open.
* The group Register locks gives the rules of a lock.
* "Reads back" means the value that a read of the register returns.
* A pad type "keeps" an attribute bit when the pads of that type implement the bit ([Pad Attributes](../programmers_guide.md#pad-attributes)).
* A pad type keeps the same bits on every pad of the type, and the bits that it keeps never change.
* No document lists the bits that each pad type keeps, so the rows fix only that the pads of one type agree.
* A one-bit field is kept when its bit is kept, and each bit of `slew_rate` and of `drive_strength` is kept or not kept on its own ([Pad Attributes](../programmers_guide.md#pad-attributes)).

## Sleep retention

Conditions:

* In these rows, a pad is any MIO pad `p` or any DIO pad `d`.
* A pad's status bit is the pad's bit in `MIO_PAD_SLEEP_STATUS` or in `DIO_PAD_SLEEP_STATUS`.
* Sleep entry is a rise of `sleep_en_i` from 0 to 1.
* The rows for sleep modes 0 to 3 hold while the pad's sleep mode has not changed since sleep entry.

## Register block and bus

Security-relevant ([Groups](#groups)).

Conditions:

* A "failed request" is a request whose command integrity code does not match, or whose data integrity code does not match ([Usage of User Bits](../../../../../ip/tlul/README.md#usage-of-user-bits)).
* No document says whether the data integrity code of a read is checked, because that code covers the write data ([Usage of User Bits](../../../../../ip/tlul/README.md#usage-of-user-bits)).
* These rows follow the design, which checks the data integrity code of every request.
* The pinmux's alert sender answers a ping of the alert handler with an alert event, which is a full handshake on the alert and acknowledge pairs.
* The alert handler takes that handshake as the answer to its ping ([Ping Testing](../../../../../top_darjeeling/ip_autogen/alert_handler/doc/theory_of_operation.md#ping-testing)).
* The "in-band reset" is the alert handler's re-initialization.
* During the in-band reset, the alert handler puts a signal integrity error on its ping and acknowledge pairs on purpose ([Employed Solution](../../../../../top_darjeeling/ip_autogen/alert_handler/doc/theory_of_operation.md#employed-solution)).
* A request has an "illegal combination of address, size and mask" when its address is not aligned to its size, when its size is greater than 2, or when its mask has a bit set outside the access.
* A `PutFullData` request also has an illegal combination when the mask bit of a lane inside the access is 0.

## Wakeup detectors

Conditions:

* The detector index `w` runs from 0 to `NWkupDetect` - 1, and a cycle in these rows is a cycle of `clk_aon_i`.
* The watched signal and the forwarded value are defined in the [Terms](#terms).
* The register values in these rows are those that the AON logic holds once a write has crossed into the AON domain.
* The rows hold while an enabled detector keeps its mode.
* The other fields of the detector may change while it is enabled, although no specification states what such a change does.
* The rows hold at every value of `sleep_en_i` and of the scan mode, and also while `clk_i` is stopped.
* The rows are checked from the filter's fourth sample after the AON reset `rst_aon_ni`.
* The timed rows ([`REQ_WKUP_09a`](#req_wkup_09a) to [`REQ_WKUP_10b`](#req_wkup_10b)) hold while `CNT_TH` is 1 or greater.
